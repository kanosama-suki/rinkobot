# Kanobot

一个运行在 DSH 宿主中的陪伴型自进化机器人。她同时是家人、恋人和生活协助者，目标不是做一个套着人格外壳的通用任务代理，而是建立连续、可恢复、可审计的长期关系。

> 当前状态：M3.6 上下文预算与时间感知已完成（2026-11-05），完整 M3 仍在进行。仓库里已有可运行的 DSH Host 插件、严格配置加载器、版本化事件与纯 reducer、SQLite 持久化、确定性快照、回收站/彻底清除、独立墓碑库、每日备份、复用 DSH 登录态的网页聊天和 SSE 流、连接本地 Magpie 的精确模型网关与调用审计、FTS5 双列中文检索、聊天前记忆召回注入、单次模型调用返回的 `reply`/`memoryCandidates`/`appraisal`/`commitments` 信封、正文逐字流式显示、appraisal 状态事件、承诺正文与事件、所有者记忆面板、确定性回复风格检查、所有者操作审计、紧急停止/`STOP` 文件双重开关，以及当前时间、星期、沉默时长、定性状态和分块上下文预算。对话仍使用占位人格；可配置视觉模型、不经过 DSH 的本地开发入口、真实模型比较和主动消息尚未实现。边界与证据见 [M3.0](docs/m3-acceptance.md)、[M3.1](docs/m3.1-acceptance.md)、[M3.2](docs/m3.2-acceptance.md)、[M3.3](docs/m3.3-acceptance.md)、[M3.4](docs/m3.4-acceptance.md)、[M3.5](docs/m3.5-acceptance.md) 和 [M3.6](docs/m3.6-acceptance.md) 验收记录。

## 当前确定的方向

- DSH 作为宿主，陪伴核心、状态、记忆、主动性和进化治理自行开发。
- 不使用巨型 FSM；采用事件驱动状态、纯 reducer、策略层、事件日志和快照。
- 人格是燐子（rinko），设定放在 Git 外；仓库里的示例和测试只用占位身份。
- 先在本地 Windows 上开发和使用，之后迁移到 Linux 服务器；主模型选型后置到项目完工后，视觉模型独立配置且不写死厂商或模型名。
- 第一个可以日常使用的版本是 M4：网页聊天、长期记忆、每日整理、每 1～2 小时主动一次和提醒。
- 个人 QQ + NapCat 后置，用户已接受风控/封号风险；工程上仍做白名单、限频、去重和熔断。
- 公开发送和 LLM 审查整体后置，当前不实现公开渠道。
- 配置按模块拆分，一个功能模块一个 TOML 文件；个人配置和凭据不进入 Git。
- Linux 桌面 VM、浏览器阅读、单机游戏和受控自进化按里程碑逐步验证。
- 状态由版本化事件和纯 reducer 驱动；快照可重复回放，数据库损坏或 schema 不兼容时拒绝启动。
- 主库备份不包含独立墓碑库；恢复旧主库后先重放墓碑，旧删除内容不会复活。

## 不承诺的事情

- 当前是可本地链接进 DSH 测试 Profile 的私有开发包，不是已发布的可安装版本。
- M3.6 已经能把当前时间、星期、沉默时长和定性状态注入提示词，并在字符预算内优先保留身份规则和当前消息；但场景测试仍使用脚本化占位回复，可配置视觉、本地开发入口、真实模型比较和生产部署尚未验收。
- 不保证个人 QQ/NapCat 长期稳定，不保证不被平台风控。
- 不把第三方插件的 README、测试数量或收录状态当作安全审计。
- 不把虚拟身体状态当成真实生理状态，也不把关系数值当成用户价值评分。
- 数据库文件扫描不等于 SSD、文件系统快照、云备份或模型服务商侧的物理擦除。
