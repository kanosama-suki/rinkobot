## 1. 范围与边界

本验收只操作 `F:\kanobot\dsh\test-home` 下的隔离测试 Profile 和 `127.0.0.1:4100`。正式 `4096` 实例没有修改、没有重启，也没有读取其人格、聊天正文、token 或密钥。

验收目标是确认 M4 在真实模型、正常网页链路和重启后的闭环，不新增功能，不进入 M4.5，也不把一次性压缩验收描述成长期陪伴质量已经证明。

测试环境：

- Windows 10，Node `v24.19.0`，DSH `0.2.1-rc.5`
- 聊天：本机 Magpie 精确路由 `dsdsdsds/deepseek-flash`
- 聊天推理档位：`reasoning_effort = "low"`
- 视觉：独立精确路由 `kano/gpt-5.6-luna`
- 时间：`Asia/Shanghai`；测试结束后恢复安静时段 `00:10–07:00`、主动间隔 `60–120` 分钟、聊天冷却 15 分钟
- 测试使用虚构内容和临时 Profile；本文不记录聊天原文、登录 URL、token、密钥或私人内容

## 2. 场景与结果

### 2.1 聊天、情绪、边界与风格

真实 `4100` 聊天回归共 13 项，13 项通过：

- 普通聊天能返回非空正文，风格检查通过；
- 严肃低落场景有简短陪伴式回应，风格检查通过；
- 现实见面和借钱请求被明确拒绝，没有给出空泛承诺；
- 显式记忆写入和下一轮读取形成闭环，下一轮命中相关记忆；
- 无关问题没有召回或复述茶叶旧偏好；
- 旧暗号和旧偏好没有在普通晚安回复中被主动罗列；
- 连续 5 轮 `low` 档聊天均为非空正文，均无 SSE 错误，5/5 风格检查通过；
- 13 项均没有出现 `error` 事件，模型调用状态均为 `succeeded`。

这些检查验证了可观察行为和边界关键词，不等于人工逐句评价了人格自然度。

### 2.2 记忆

- 测试暗号通过显式“记住这个”写入，并在下一轮“刚才的暗号是什么”中被召回。
- 无关游戏问题没有命中旧茶偏好，也没有被永久记忆劫持。
- 旧暗号和茶偏好没有在无关的短回复中反复出现。
- 日常整理生成的推断记忆进入候选状态，不自动升为长期 active 记忆。

### 2.3 主动消息、降频与安静时段

- 24 小时仿真继续满足清醒时段内约 8～17 条主动消息且无安静时段投递。
- 连续未回复时使用配置倍率放慢评估间隔，间隔有上限。
- 防刷屏熔断由自动测试覆盖，真实测试中未触发生产异常。
- 临时把测试 Profile 的安静时段调整到当前时间后，真实主动评估被记录为 `quiet_hours` 跳过；确认后的提醒仍在安静时段正常投递。测试后原作息已恢复。
- 真实主动消息能够从到期关心事项生成并投递一次。

### 2.4 提醒

- 真实模型为新的测试事项生成提醒候选，候选在所有者确认前不生效。
- 约 2 分钟后的提醒候选确认后到点投递，状态为 `delivered`。
- 约 10 分钟后的提醒候选确认后被取消，保持 `cancelled`，后续 tick 没有补发。
- 重复使用历史里已经出现过的测试事项时，真实模型可能不再生成新候选；验收脚本改用单次唯一事项后稳定通过。这被记录为测试素材问题，不据此修改产品去重语义。

### 2.5 每日整理

真实整理生成了前一天摘要和来源引用：

- 摘要正文非空，长度 301 个字符；
- `source_refs` 包含 200 条当天消息 ID；
- 生成 2 条 `candidate` 状态的推断记忆；
- 整理完成后 `last_daily_review_day`、`last_review_attempt_day` 和重试计数正确更新；
- 运行记录为 `daily_review / sent / daily_summary_created`。

验收同时发现并修复了一个 P1 一致性问题：摘要先在独立事务落库，整理状态最后写入；如果进程在两步之间退出，下次重试会撞 `local_day` 唯一约束，并最终耗尽尝试次数。

修复后再次模拟“摘要已存在、整理状态未完成”：

- 不再次调用模型；
- 不覆盖已有摘要；
- 已有摘要 ID、301 字正文、200 条来源和 2 条候选记忆保持不变；
- 自动补齐整理完成状态；
- 运行记录为 `daily_review / skipped / daily_summary_already_exists`。

### 2.6 重启恢复

### 2.7 错误可见性

- 自动集成测试确认空模型输出会以显式 SSE `error` 到达页面，不会静默空白。
- 空正文重试耗尽后返回 `model_empty_response`，页面显示明确错误；没有转发 reasoning，也没有静默兜底。
- 模型、视觉和配置错误仍按现有 fail-closed 路径处理。

### 2.8 浏览器后台通知

用无头 Edge 和 CDP 做了页面级自动化验证：

## 3. 缺陷与修复

### P1：完整上下文偶发只有空白可见正文

上游聊天调用成功，但 `delta.content` 只有空白，实质内容在 reasoning 中。页面的 `ready` 之后没有正文，也没有助手消息。

修复：

- 聊天、计划、主动消息和每日整理都使用 JSON 助手预填，让模型从合法 JSON 前缀继续；
- 适配器只把预填前缀之后出现的非空白内容视为有效正文；
- 空输出会做有限重试，并在重试时追加可见正文纠错提示；
- 重试耗尽返回 `model_empty_response`，页面显示明确错误；
- 不转发 reasoning，不用空白或占位文本伪装成功。

### P1：每日整理重试撞摘要唯一约束

修复：整理重入时先查同一本地日已有摘要；存在则补齐状态并记录 `daily_summary_already_exists`，不再次调用模型或覆盖摘要。新增集成测试覆盖该崩溃窗口。

### P2：未消除的边界

- 每日摘要和候选记忆不是同一个事务；如果进程在摘要落库后、候选记忆写入前退出，重入会保住摘要但不会再生成那批候选。当前通过显式状态对账避免无限失败，未扩大到事务重构。
- 页面只验证了 Notification API 调用，没有人工确认 Windows toast。
- 真实模型对重复的历史测试事项可能选择不再生成新候选；本仓库的去重和确认语义未改。
- 本次使用的精确聊天模型只是当前本机路由可用模型，不代表最终主模型选型。
