## 2. 已实现内容

### 2.1 配置化上下文预算

`system.toml` 新增 `[context]`，必填且由严格 loader 校验：

```toml
[context]
max_prompt_chars = 20000
max_state_chars = 480
max_memory_items = 5
max_memory_item_chars = 500
max_memory_chars = 3000
max_history_messages = 40
max_history_chars = 8000
max_message_chars = 4000
```

- 字符预算按 Unicode 码点计，不冒充上游 tokenizer 的精确 token 数。
- `max_history_messages` 和 `max_history_chars` 只限制当前消息之前的历史。
- `max_message_chars` 在写入用户正文之前校验；超限不会留下孤立消息。
- 示例配置和 4100 测试 Profile 已同步；正式 4096 配置未改。

### 2.2 固定分块与裁剪顺序

新增纯函数组装器 `src/core/chat/context.ts`。每轮上下文由以下部分组成：

1. 身份、风格、输出协议和优先规则；
2. 当前时间、星期、沉默时长和定性状态；
3. 长期记忆；
4. 最近对话；
5. 本条用户消息。

总预算超限时：

1. 先删最旧的对话，并跳过失去对应提问的开头助手消息；
2. 历史删完仍超限时，才从末尾删除相关度最低的长期记忆；
3. 身份/优先规则和本条消息永不裁剪；
4. 固定内容本身仍放不下时 fail-closed，返回 `context_budget_exceeded`，不静默截断规则。

当前消息只在消息数组末尾出现一次，不会同时作为历史副本重复发送。

### 2.3 时间与状态描述

提示词现在包含：

- 配置时区中的日期、星期和时分；
- 配置时区名、UTC 偏移和规范 UTC 时间；
- kano 距上次用户发言的时长；
- 由 `activity`、精力、社交电量、情绪和关系状态生成的一两句行为提示。

原始状态数值不进入提示词。例如低精力会变成“有点困，回复可以短一点”一类描述，而不是 `energy=0.2`。

单次 JSON 信封的输出规则新增要求：相对时间必须以“当前情境”提供的当前时间为基准，`dueAt` 输出带毫秒的规范 UTC ISO。

### 2.4 记忆召回时间

- 检索阶段先不写 `lastRecalledAt`。
- 上下文组装完成后，只标记真正进入提示词的记忆。
- 因数量或总预算被裁掉的记忆不会被误记为“刚被想起”，避免抬高后续检索排序。

### 2.5 版本与 schema

- 插件版本从 `0.8.0` 升到 `0.9.0`，同步修改 `package.json`、`package-lock.json` 和 `src/plugin/version.ts`。
- SQLite schema 保持 v6，没有新增迁移。
- 启动报告新增 `contextMaxPromptChars` 和 `timezone`，便于确认真实实例装配了哪些配置。

- 不经过 DSH 的本地开发入口、统一审计视图和风格检查失败自动重生成仍属于完整 M3 的剩余工作。
- 主模型比较和选型按 kano 的决定后置到整个项目完工后。
