## 3. 对“像真人”的理解

真人的记忆不是每轮把所有事实复述一遍，而是：

1. **选择性注意**：重要、情绪强、反复出现或未来有用的事更容易留下。
2. **选择性提取**：被问到、话题直接相关或时间情境触发时才想起来。
3. **表达克制**：记得不等于必须说出来；无关问题不能被旧偏好劫持。
4. **重复抑制**：刚提过的事短期不反复提，避免像在背记忆清单。
5. **时间延续**：昨天生病，今天可以关心恢复；关心一次后转为普通记忆，不每轮重复。
6. **遗忘与巩固**：普通小事淡化，重要事件、关系修复和承诺留下；每日整理只生成候选，不把模型猜测直接升级成事实。
7. **来源感**：能区分“kano 亲口说过”“燐子自己推断”“在网页上看到”；推断必须保留置信度。

这对应一句设计原则：**体验像人，证据像机器。** 对外表现为自然的注意力、遗忘和关心；内部仍保留来源、引用、时间、分数和可审计的取舍理由。

## 4. 对 Rinkobot 的具体取舍

### 4.1 第一版保留

- 长期记忆继续使用 SQLite FTS5，不先引入向量数据库、知识图谱或 SM-2 复习。
- 写入仍区分 `user_stated`、`rinko_inferred` 和 `external`，敏感/第三人内容先进入候选。
- 召回前先判断问题意图和主语：问燐子自己的偏好，不能用 kano 的偏好代替回答。
- 按当前问题的主题覆盖率设相关性门槛；重要度只作为同等相关度后的排序因素。
- 对刚被召回的条目做重复抑制，而不是因为最近提过就继续加权。
- 普通 `user_stated` 内容默认只成为候选；明确“记住这个”、重要事件或所有者确认才直接进入可检索长期记忆。
- 显式“记住这个”有确定性兜底：即使模型漏输出 `memoryCandidates`，也从短而直接的指令中保存一条记录。
- 召回只在明确询问、当前话题直接相关或时间/情境需要时发生；允许以后在主动消息里偶尔自然提起，但不设每轮固定展示。

### 4.2 后续再做

- 把记忆的逻辑分类稳定为 `profile`（用户画像）、`episodic`（情景）、`care`（需要跟进的时间和关心事项）、`relationship`（关系事件、伤害和修复）。当前 `kind` 字段已能承载这些值，但还没有独立的 schema 和时间跟进表。
- 时间性关心事项使用 `occurredAt`、`followUpAt`、`resolvedAt`、`lastExpressedAt`，并和普通记忆分开，防止生病、考试之类的事被每轮复述。
- 在 FTS 稳定、有评测集之后，通过 `MemoryRetriever` 接口接本地 embedding；先证明 FTS + 门槛的误召回率，再决定是否需要向量。
- 每日整理时根据显著性、情绪强度、重复出现和未来用途提升候选，不把临时情绪或一句寒暄永久化。
- 敏感内容、第三人信息和关系冲突可以引入更严格的审批或二次确认；普通日常记忆不逐条打扰所有者。

### 4.3 明确不采用

- 不把七层记忆全部在每轮或首轮无条件注入。
- 不把模型自己说“这条很重要”当作事实。
- 不把“总能召回 5 条”作为质量目标；没有足够相关的记忆时应返回空。
- 不因为一条记忆被标成 `permanent` 就让它压过当前问题。
- 不在 M4 第 0 步引入向量检索、知识图谱、复杂复习算法或第三方运行依赖。

## 5. 当前实现映射

- `src/core/memory/recall.ts`：问题意图、主体判断、主题词、相关性分数、同等相关度排序。
- `src/core/memory/explicit.ts`：显式“记住这个”的短指令识别和兜底提取。
- `src/core/memory/service.ts`：普通陈述进候选、明确指令直接 active、有界召回和最终 `lastRecalledAt` 更新。
- `src/core/storage/store.ts`：FTS 查询先按检索相关性，再按重要度和重复抑制排序。
- `src/core/chat/context.ts`：提示模型不要把记忆清单化，也不要用 kano 的偏好替代燐子自己的回答。
- `src/core/chat/service.ts`：把显式记忆检测接入聊天信封，并在模型漏候选时执行确定性兜底。

## 6. 已知限制

- 当前主题判断是确定性中文规则，能覆盖“喜欢玩游戏不能插喝茶”这类已知回归，但不等同于语义理解。
- 需要更多真实对话样本评估同义词、反问、长句和隐式回忆请求；目前自动测试只证明规则边界，不证明真实模型一定自然。
- 记忆分类和时间性关心还没有落地到独立表；主动回忆仍要等 M4 主动性模块。

## 7. dsh-hippocampus 只读复核（2026-11-06）

### 7.1 快照与结论

- 仓库：`https://github.com/coner13/dsh-hippocampus`
- 复核版本：`0.2.40-r8`，提交 `037932c1e3422eceb53249eb156cdeeb760b9e79`
- 许可证：`PolyForm Noncommercial 1.0.0`，个人使用和研究可以，但不是 OSI 开源许可证；商业用途需要单独授权，分发修改版有 Required Notice 要求。
- 自检结果：`node selftest.mjs` 340/340 通过；`node smoke.mjs` 74/74 通过。测试证明的是它自己的边界和回归，不等于真实模型下的陪伴效果。
- 总体判断：**值得作为记忆交互设计参考，不直接安装或复制为 Rinkobot 的记忆底座。** 最有价值的是“记忆存在感分层”和“原话证据链”，不是替换现有的 SQLite/FTS5。

### 7.2 值得借鉴的机制

1. **预激活 / 完整回忆 / 原话核查三层分离**
   - 每轮只给最多三行“以前碰过这件事”的弱提示，不预加载整段原文。
   - 明确询问时才展开完整情景；要确认一句话是否真的说过，则用精确原话查询，不拿“最像的一段”冒充证据。
   - 输出分“想起来了”和“有点像是这一段，但我不确定”两档，降低把相似当成事实的概率。

2. **Episode（情景段）而不是单条消息记忆**
   - 按会话切换、2 小时间隔、告别语和话题漂移切段。
   - 同一段最多取少量片段，回忆时按时间顺序展开，不把一段经历拆成互相竞争的事实卡片。

3. **原话、推断和动作分开**
   - 原始发言保留来源、会话和位置；从思考中抽出的决定、教训、线头和预测明确标记为“我的推理，不是原话”。
   - 工具调用和网页内容记为动作或外部经历，不冒充用户说过的话。

4. **用进废退和沉默闸**
   - 强命中才增加“被想起”的次数，弱命中只记“碰过”，权重更低。
   - 没有足够相关的记忆时返回空，不为了凑数补最近旧事。
   - 时间衰减采用幂律，内容相关性优先，时间接近时才作为排序裁判；这些具体参数不能照抄，必须用 Rinkobot 自己的真实语料重新标定。

5. **冻结回归样本**
   - 用固定的“应该想起 / 不应该想起”样本测量误召回和漏召回，而不是只靠主观感觉调阈值。

### 7.3 不直接采用的部分

- 它是 DSH 专用插件，依赖 DSH 会话事件、系统提示注入和工具接口；直接接入会与 Rinkobot 的 SQLite、`bodies`、事件和墓碑形成第二套真相源。
- 它采用按工作区划分的 JSONL 原始流，偏“只增不改”，没有 Rinkobot 现有的正文清除、墓碑、所有者审计和恢复边界。
- 它只做中文二元组和 BM25 词法检索，不做向量检索；换一种说法可能找不到。这个“宁可漏，不把像当成是”的原则值得保留，但不能据此否定未来经过评测的 embedding。
- 它不承担人格基线、关系状态、时间性关心和权限治理；这些不能从它那里替代。

### 7.4 对 Rinkobot 的后续改进建议

1. 为长期记忆补充可追踪的来源消息引用，至少能区分“用户原话”“燐子推断”“外部内容”和“动作经历”。
2. 在上下文层实验“短提示预激活”与“按需完整回忆”的分离；只有明确回忆请求或强相关时才展开全文。
3. 增加会话内的重复抑制，避免同一条旧事在连续几轮被反复强调；当前 `lastRecalledAt` 只能部分做到这一点。
4. 把情景段（episode）作为每日整理和记忆抽取的上层单位，减少单条消息碎片化。
5. 建立冻结的记忆回归集，优先测“不该想起”“不该重复”“该想起却没想起”，再决定是否需要向量检索。
