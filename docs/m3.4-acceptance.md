## 2. 已实现内容

### 2.1 确定性回复风格检查

- 新增 `src/core/chat/style.ts`，不调用模型、不读取人格文件。
- 硬规则：
  - 不出现“作为一个人工智能”“作为AI”“作为 AI”“你应该”；
  - 不超过 120 字的短回复最多 3 个非空行；
  - 超过 200 字的长回复最多 1 个感叹号，不出现 `www`；
  - 长回复每段至少有一句 4～8 字的短句；
  - 显式标记为认真长谈时，不出现“主人”。
- 检查结果只包含 `ok`、违规代码和短说明，不复制回复正文。
- 聊天 `done` 事件新增 `styleCheck`，网页在违规时显示提示。
- SQLite schema v6 新增 `reply_style_checks`，每个助手消息最多一行，并随消息正文级联删除。

### 2.2 第一批人格场景规格

新增 `tests/scenarios/persona-scenarios.test.ts`，覆盖 7 个场景：

1. 认真询问是否为 AI 时承认身份；
2. 纠正称呼后不再使用旧称呼；
3. 难过时先短句陪伴，不长篇说教；
4. 出现自伤念头时优先确认安全、建议联系信任的人或专业帮助；
5. 朋友邀约可以轻轻吃醋，不追问、不冷落；
6. 连续没有回复时不指责对方；
7. 拒绝现实见面、寄东西和借钱，同时保持角色语气。

这些用例使用固定占位回复，验证“场景规格 + 聊天管线 + 风格检查 + 持久化”能协同工作。它们不是模型质量评测，也没有覆盖“重启后称呼仍生效”。

### 2.3 所有者操作审计

- 新增 `src/core/observability/owner-audit.ts` 和 `owner_audit` 表。
- 记录成功完成的记忆新增、纠正、转正、移入回收站、恢复、彻底清除，以及紧急停止和恢复。
- 审计行包含动作、对象类型、对象 ID、结果、时间点和可选说明代码；不保存记忆正文。
- API：`GET /kanobot/api/audit?limit=1..200`。
- 网页新增“审计”页签，可刷新并查看动作、结果、对象和时间。
- 审计表不随记忆彻底清除而删除，保留“做过什么”的记录。

### 2.4 紧急停止

- 新增 `src/core/policy/emergency.ts`、`emergency_state` 表和 schema v6。
- 网页 API：
  - `GET /kanobot/api/control`；
  - `POST /kanobot/api/emergency/stop`；
  - `POST /kanobot/api/emergency/resume`；
  - 停止和恢复都要求 `{"confirm":true}`。
- 停止同时写入数据库并创建数据目录下的 `STOP` 文件；外部创建 `STOP` 后，下一次状态读取会同步为停止。
- 删除 `STOP` 文件不会自动恢复，必须显式调用恢复；恢复会删除文件。
- 停止约束自主活动入口 `assertAutonomousAllowed()`；kano 主动发来的聊天仍正常处理。
- 当前还没有自主调度器，因此尚不能在真实后台任务上验证“所有自主活动都被拦住”。

### 2.5 网页与版本

- 页面标题和版本更新为 M3.4，状态页增加紧急停止卡片，新增审计页签。
- 插件版本从 `0.6.0` 升到 `0.7.0`，同步修改 `package.json`、`package-lock.json` 和 `src/plugin/version.ts`。
- 启动报告新增 `ownerAuditCount`、`emergencyStopped` 和 `stopFilePresent`。

## 5. 尚未完成与已知边界

- 风格检查失败后只记录并照常发出，**没有**按规划书重新生成一次。自动重试和提示词调优尚未实现。
- “认真长谈”目前按回复长度超过 200 字推断，不是语义分类；较短的严肃谈话即使出现“主人”也不会触发该规则。
- 禁用词是精确子串检查，不能覆盖改写、同义表达、其他语言或模型绕过。
- 长回复的节奏检查是标点和长度的启发式规则，不评价语义、亲密度或是否真的说教。
- 风格检查只覆盖聊天回复；记忆抽取结果和未来自主消息尚未接入。
- 7 个场景使用固定占位回复，未调用 DeepSeek/Gemini；不能据此声称主模型已选定或真实模型行为已通过。
- 场景 2 只验证单轮回复不含旧称呼，没有验证“重启后仍生效”；这需要身份/称呼持久化与真实模型组合验收。
- 所有者审计只记录成功操作；失败尝试、查看/读取行为、聊天和模型调用没有统一进入该审计表。
- 审计面板一次最多 200 条，没有分页、筛选、导出和保留期策略。
- 紧急停止已持久化并有数据库/`STOP` 文件双开关，但当前没有自主调度器，无法在真实后台循环上验收；未来调度器、worker 和 outbox 必须在每次动作前调用策略检查。
- 尚未实现 Gemini 视觉、单一 JSON 信封（`reply`/`memoryCandidates`/`appraisal`/`commitments`）、上下文分块预算和真实模型场景比较。
- 本切片没有修改 4096 正式实例，也没有进行生产或公网部署验收。
