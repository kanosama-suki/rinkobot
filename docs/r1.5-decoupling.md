# R1.5：从 DSH 插件解耦为独立程序

> 日期：2026-11-11
> 产品版本：`0.21.0`
> SQLite schema：v12（未修改）
> 归档标签：`archive/dsh-plugin-0.20.0`
> 许可证：MIT

## 1. 决定

主分支只发布独立 Rinkobot，不再把 DSH 当作插件宿主、运行前置条件、模型
provider 或产品会话体系。未来的 DSH 只能作为可选的外部执行器/连接器，
通过窄接口联动；它不能拥有主数据库、调度器、主写入者或产品生命周期。

## 2. 删除的代码

- `src/plugin/` 下的 DSH 插件入口、生命周期、模型桥和 bundle 配置；
- `src/model-providers/dsh-chat.ts` 与 `dsh-types.ts`；
- `scripts/m1-lifecycle.ts`；
- DSH 模型桥和插件生命周期的集成测试；
- 设置页中的 DSH provider、route 和宿主模型发现界面。

完整旧实现保存在 Git 标签 `archive/dsh-plugin-0.20.0`，没有改写 Git 历史。

## 3. 契约变化

| 项目 | R1 及以前 | R1.5 |
| --- | --- | --- |
| 产物 | DSH 插件 + 独立程序 | 独立程序 |
| 包名 | `@kanobot/dsh-plugin` | `rinkobot` |
| 模型 provider | `mock` / `magpie` / `dsh` / `openai-compatible` | `mock` / `magpie` / `openai-compatible` |
| 模型路由 | `route` 可用于 DSH provider | 删除；旧配置 fail-closed |
| 登录 | 可复用 DSH 会话 | 运行时一次性 bootstrap 登录 + 短期 Cookie |
| 产品入口 | DSH 内 `/kanobot/` + 独立 WebUI | 独立 WebUI |

旧 `system.toml`、`model-settings.json` 中如果仍有 `provider = "dsh"` 或
`route` 字段，启动会明确失败并给出迁移提示，不会静默切换模型。

对外品牌已统一为 Rinkobot。为兼容现有数据和运行实例，`/kanobot/` 路径、
`kanobot.sqlite`、`kanobot.lock`、`KANOBOT_*` 环境变量和内部 `Kanobot*`
类名暂不迁移；这些标识会在单独的数据/接口迁移中处理。

## 4. 未改变的部分

- 人格、关系、记忆、主动性、提醒、QQ/NapCat、审计和 schema v12；
- 一个核心、一个主数据库、一个调度器、一个主写入者；
- 所有者 QQ 私聊并入 `main`，其他私聊/群聊隔离；
- 本地回环监听、一次性登录、备份恢复和 systemd 部署材料。

## 5. 验证边界

本轮 Windows 自动测试 `327/327` 通过，覆盖独立启动、旧配置拒绝、网页聊天、
QQ mock、记忆、提醒、主动消息、备份恢复和配置校验；`check:case`、
`config:check`、前端语法检查、`git diff --check` 和 `npm pack --dry-run`
也通过。打包预检只包含 `config/examples/`，不会把 `config/local/`、运行时
数据、secret 或旧构建产物带进包。真实 NapCat/QQ、真实第三方模型、Linux
systemd 实机常驻仍需在实际部署环境验收。
