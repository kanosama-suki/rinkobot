## 2. 已实现内容

### 2.1 记忆写入与候选规则

新增 `src/core/memory/`：

- 用户明确陈述、且不标为敏感或第三人内容：立即写成 `active`。
- `rinko_inferred` 推断、`external` 外部内容、`sensitive` 和 `third_party`：只能先写成 `candidate`。
- 候选不会进入全文检索；只有所有者显式调用 `promote` 后才转为 `active`。
- 每条记忆保存来源、置信度、敏感级别、重要程度、创建时间、正文引用和原话引用。
- 正文仍只写入 `bodies`；记忆记录本身不内嵌正文。
- 服务层将单条记忆和引用限制在 4,000 字符内，空文本、非法来源、非法置信度和非法 kind 在写库前拒绝。

### 2.2 FTS5 双列检索

SQLite schema 从 v3 升到 v4，新增 `memory_search` FTS5 虚拟表：

- `word_text`：用 `Intl.Segmenter('zh-CN')` 切出的词；
- `char_text`：逐字索引的字母和数字，解决“茶”这类单字短词；
- 只索引 `active` 记忆；候选、已替代、回收站和彻底清除记录不可检索；
- 查询词经过 Segmenter 提取和 FTS5 引号转义，不把用户原文直接拼接成查询语法；
- 多个查询词使用 AND，避免“的/不”等常用字把无关记忆召回；
- 排序依次考虑重要程度、最近提起时间和 bm25；
- 检索命中后更新 `lastRecalledAt`，该字段不参与 FTS 内容，因此不重建索引。

### 2.3 纠正、回收站与清除

- 纠正会建立新记忆并在同一事务中把旧记忆标为 `replaced`，写入 `replacedBy`。
- 旧记忆保留正文作为证据，但 FTS 行会删除，不再被检索。
- 候选可由所有者单独转正，不会因为检索或时间流逝自动转正。
- 回收站隐藏记忆并移除 FTS 行；在 30 天保留期内恢复后重建索引。
- 彻底清除会删除记忆正文、记忆行和 FTS 行，随后继续执行 `VACUUM`、WAL checkpoint 和完整性检查。
- 文件级清除测试扫描主库、墓碑库、FTS 附属文件和 sidecar，确认测试原文不再出现。

### 2.4 迁移与恢复

- v3 → v4 原地创建 FTS 表，不删除旧事件、正文、聊天、模型调用或记忆。
- 启动时会收敛索引：移除不对应 `active` 记忆的行，并为缺失的 active 记忆补建索引。
- v1/v2 旧库仍可按 v2 → v3 → v4 顺序迁移。
- 重启后 active 记忆仍可检索，回收站状态和候选状态不变。

## 5. 尚未完成与已知边界

- 聊天模型还没有结构化输出，因此不会自动提交 `memoryCandidates`；本切片只完成可调用的记忆核心。
- 网页没有记忆查看、添加、纠正、候选转正、回收站或彻底清除入口。
- 没有经过 DSH 登录态的 memory HTTP API；不能把当前能力描述成可用的面板功能。
- 每日摘要、印象深刻的永久记忆、普通记忆淡化和反复提起加权重属于 M4。
- 没有真实模型参与的“记住这条”与称呼纠正端到端验收。
- 查询使用 AND，召回偏精确；后续接入完整聊天上下文时，需要用结构化查询词或检索策略评估是否足够。
- 没有向量检索；只有 FTS5 双列方案通过了当前的中文短词验收。
- 文件扫描只能证明本机 SQLite 文件不再包含测试原文，不能证明 SSD、文件系统快照、备份或模型服务商侧已物理擦除。
- 本切片没有修改 4096 正式实例，也没有进行生产或公网部署验收。
