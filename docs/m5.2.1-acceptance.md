## 2. 问题与修复

### 2.1 QQ 私聊没有进入“我们的对话”

根因：测试 Profile 启用了 QQ，私聊白名单也存在，但没有显式配置 `owner_qq`。消息实际保存在 `qq-private-<id>`，不是消息丢失；没有所有者配置时，核心不能安全判断哪一条私聊属于所有者。

修复：

- 不从白名单里的第一个账号推断所有者，`owner_qq` 必须显式配置且同时位于 `private_allow`。
- 状态接口新增 `ownerQqConfigured`（当前已启动运行时是否采用）和 `ownerQqSaved`（磁盘配置是否已有），两者分开；保存 `owner_qq` 后到重启前仍显示未生效，避免页面误报。
- QQ 已启用但缺少所有者时，网页显示警告：QQ 私聊目前只会出现在“全部对话”。已保存但未重启时，提示改为“所有者 QQ 已保存，但当前实例尚未重启”，不再说成“还没设置”。
- 独立程序和 DSH 插件启动时，如果已有 `owner_qq`，把既有 `qq-private-<owner>` 历史幂等并入 `main`：
  - 只更新 `messages.conversation_id` 和 `model_calls.conversation_id`；
  - 保留正文、消息 ID、`messages.seq` 和模型调用审计；
  - 不复制消息，不重排历史；
  - 目标行不存在时创建 `main` 会话；
  - 重复启动不重复迁移。

### 2.2 “加载更早的消息”按钮位置

修复：

- HTML 增加 `.messages-shell` 包裹层，`#history-more` 绝对定位在消息区顶部。
- `#messages` 仍是唯一消息滚动容器；按钮不再占据消息流高度。
- 只有同时满足“还有更早消息”“`messages.scrollTop <= 24`”“当前不在加载中”时才显示。
- 加载更多后继续使用原高度差锚点，保持当前阅读位置；再滚回顶部才重新显示按钮。

### 2.3 档案会话名称可编辑

持久化：

- `conversations` 新增 nullable `display_name`，schema 从 v11 升到 v12。
- 旧会话迁移后 `displayName === null`。
- 不修改 `conversationId`、正文、消息顺序、`messages.seq` 或模型上下文。

默认标签：

- `main`：`我们的对话`。
- `qq-private-*`：原始 `qq-private-*`。
- `qq-group-*`：原始 `qq-group-*`。

改名规则：

- 只允许修改非 `main` 会话；`main` 返回 409。
- trim 后最多 60 个 Unicode 字符，拒绝控制字符。
- 空字符串或 `null` 恢复默认标签。
- 不存在的会话返回 404；请求体只接受 `displayName`。
- 复用现有 Web 鉴权、请求体上限和错误格式。

接口：

```text
PUT /kanobot/api/conversations/:id
Content-Type: application/json

{ "displayName": "夜间私聊" }
```

页面在“全部对话”的会话选择器旁提供名称输入、保存和恢复默认按钮；改名后更新选择器和已加载档案消息的来源标签，不重排消息。
