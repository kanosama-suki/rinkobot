## 2. 已实现内容

### 2.1 配置与启动检查

`system.toml` 的 `[model]` 现在包含：

```toml
[model]
provider = "magpie"
name = "deepseek/deepseek-flash"
base_url = "http://127.0.0.1:3425/v1"
# api_key_env = "MAGPIE_API_KEY"
timeout_ms = 120000
max_retries = 2
max_output_tokens = 4096
```

- `base_url` 只允许 `http`/`https` 回环主机，禁止 URL 内嵌凭据、query、fragment，路径必须是 `/v1`。
- IPv4、`localhost` 和 IPv6 `::1` 均可使用；Node 返回的 IPv6 方括号会先规范化再校验。
- `api_key_env` 可选，只保存环境变量名。变量已配置但为空或缺失时拒绝激活，不回显密钥值。
- `modelMode=magpie` 时，插件启动后先查询 `/v1/models`，要求配置的精确模型存在。
- 启动检查失败会阻止插件激活，不自动降级到 mock、不用 `auto/*` 路由组，也不自动切换另一个模型。
- 模型声明的输出上限低于配置的 `max_output_tokens` 时拒绝启动。

### 2.2 Magpie 流式网关

新增 `src/core/chat/magpie-model.ts`，使用 Node 原生 `fetch`，没有新增依赖。

- 请求 OpenAI-compatible `/v1/chat/completions`，启用 SSE 和 `stream_options.include_usage`。
- 支持 UTF-8 字符跨网络分片、CRLF、多行 `data:`、usage 和 `[DONE]`。
- 只把 `delta.content` 作为正文流给页面；`reasoning_content` 不进入回复、事件或页面。
- 每次 HTTP attempt 有独立超时；连接失败、超时、408、429 和 5xx 可在首 token 前退避重试。
- 已经输出正文后绝不重试，避免把两段不同的回复拼接给用户。
- 取消会中止请求并清理 reader；错误只暴露分类和尝试次数，不返回或记录上游错误正文和凭据。

### 2.3 模型调用审计

SQLite schema 从 v2 升到 v3，新增 `model_calls` 表：

- v1 → v3 和 v2 → v3 都原地迁移，旧事件、正文和聊天记录保留。
- 记录 provider、精确模型、开始/完成时间、状态、attempts、输入/输出/缓存/推理/total tokens、估算费用、响应 ID 和错误码。
- 状态只允许 `running`、`succeeded`、`failed`、`aborted`。
- 每条审计行通过外键关联会话、用户消息和成功时的助手消息；删除任一侧聊天正文都会级联删除对应调用记录。
- 每个用户请求只生成一行审计记录，内部 HTTP 重试次数单独写入 `attempts`，不会放大每日请求额度。
- 每日调用数按配置时区的本地日期统计，重启后仍可读取。

### 2.4 资源熔断与会话行为

- `resources.max_concurrent_model_calls=2` 和 `daily_model_call_limit=2000` 已从配置接入聊天服务。
- 并发额度或每日额度已满时，在写入用户消息之前拒绝请求。
- 模型失败时保留用户消息，不保存半截助手回复，也不追加互动事件；失败调用会在审计表收口。
- 成功回复、usage、估算费用和最近调用状态在重启后仍可恢复。
- 页面显示精确模型、路由 provider、今日调用、最近 token、缓存/推理 token、费用估算和最近调用状态。
- 费用只标为“估算费用”和“未标币种”，不替 Magpie 上游声明币种或账单金额。
- 页面仍明确标记为占位人格，不把 M3.1 当成正式燐子人格验收。

## 5. 尚未完成与已知边界

- 完整 M3 仍未完成，不能把本记录当作网页聊天闭环或长期记忆验收。
- 当前只有 Magpie → DeepSeek 文本路由；Gemini 官方视觉驱动和图片输入尚未实现。
- 对话仍是普通文本流，尚未实现固定 JSON 的 `reply`、`memoryCandidates`、`appraisal`、`commitments`，也没有风格检查和场景测试。
- FTS5 双列检索、长期记忆写入/纠正、完整面板操作、紧急停止和审计页面仍未实现。
- 启动时要求 Magpie 已运行且模型列表包含精确模型；路由掉线后需要用户处理，不会自动改走别的模型。
- 并发上限是单个插件实例内的计数，不是跨多个 DSH 实例的全局分布式锁。
- 费用是基于路由返回 token 和单价的估算值，缓存计价口径、价格变化和服务商账单可能不同。
- 自动测试使用伪造上游；只有 4.1～4.3 的隔离 4100 验收调用了真实本地 Magpie。
- 真实实例验收验证的是回环地址、测试 Profile 和虚构数据，不是生产部署或公网暴露测试。
