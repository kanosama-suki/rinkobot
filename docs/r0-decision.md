## 1. 已确认的决定

| 问题 | 决定 | 含义 |
| --- | --- | --- |
| Q1 产品形态 | 批准“独立核心 + 可选执行器” | Kanobot Core 自己拥有网页、QQ、调度、记忆、关系、状态和主数据库；DSH/MCP/浏览器/VM 是可替换执行层 |
| Q2 DSH 内部 UI | 首版不需要 | 独立 WebUI 是完整入口；DSH UI 只保留为未来可选观察/控制面，不成为第二套业务后端 |
| Q3 所有者会话 | 保留 M5.2.1 规则 | 只有显式 `owner_qq` 且在白名单内的私聊并入网页 `main`；其他私聊、群聊和新渠道独立存储 |
| Q4 DSH 宿主模型 | 不必须 | Magpie、OpenAI-compatible 和 mock 必须足以运行；DSH 模型只是可选项 |

补充规则：聊群或其他渠道第一次出现时，按现有规则创建独立会话；不要求提前
批量创建，也不得并入 `main`。同一平台的新私聊、新群聊各自拥有独立档案和
记忆作用域。

## 2. 架构边界

- **一个核心**：人格、记忆、关系、状态、主动性、调度和审计只实现一次。
- **一个主数据库**：生产环境只允许 Kanobot Core 进程写入主库。
- **一个调度器**：提醒、主动消息、每日整理和重试只在核心调度器内运行。
- **一个主写入者**：DSH、MCP、浏览器 worker 和 VM 不能直接打开或改写主库。
- **DSH 可选**：DSH 不存在时，网页聊天、QQ、记忆、提醒和主动消息仍须工作。
- **执行器结果不可信**：浏览器页面、命令输出、截图、文件和模型生成内容都要
  经过核心的 schema、权限、预算和审计检查。
- **独立程序是默认入口**：`src/app` 是正式装配；`src/plugin` 保留为可选
  连接器/兼容入口，不再代表产品生命周期。

## 3. M5.2.1 真实验收：部分通过

已确认的真实环境是：个人小号 + 真实 NapCat + Magpie。用户报告：

- 私聊消息能收到并回复；
- 表情包和图片可见；
- 显式配置的 `owner_qq` 私聊已正确并入网页“我们的对话”。

用户报告表明真实 OneBot 11 私聊、图片可见和 owner 合并主路径可用；本轮
没有核对每次图片是否都经过视觉模型调用。这不等于完整 QQ 验收。未验证项见
[m5.2.1-real-acceptance.md](m5.2.1-real-acceptance.md)，
包括非 owner 私聊隔离、群聊 `@`、连发聚合、多图、重启迁移、去重、提醒、
主动消息和长期稳定运行。

QQ 测试按用户决定继续缓慢进行，发现 bug 再修；R1 不等待完整 QQ 矩阵。

## 4. Linux 常驻

如果希望在不开电脑、不打开网页时仍能收 QQ、发提醒和主动联系，Kanobot Core
必须作为常驻服务运行。推荐用 `systemd` 或等价的进程监管，以非 root 用户
运行，只监听回环地址或经过鉴权的内网入口，并配置日志轮转、数据目录权限、
备份和崩溃重启。

这不需要 DSH。DSH 只是可选执行器；核心服务不应因为 DSH 未安装而停止。
Windows 开机自启已明确暂缓，Linux 常驻属于 R1 的部署任务。

## 5. R0 不做的事

- 不合并 M6.7/M6.8 WIP，不恢复 `paused_native` 或 DSH Session 桥接作为默认路径；
- 不创建新的 DSH Session 绑定，不把 DSH 侧边栏当作产品会话体系；
- 不修改源码、schema、迁移或运行时数据；
- 不把“真实 QQ 私聊部分通过”写成完整 M5 验收；
- 不在 R0 引入公开发送、每轮 LLM 审查、语音/虚拟形象或自进化实现。
