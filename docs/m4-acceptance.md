# M4 主动、提醒与每日整理验收

> 日期：2026-11-06
> 基线：`74b54db`（M4.0 记忆质量门控）
> 状态：M4 自动化实现与测试完成；真实模型试用、浏览器人工验收和一到两周日常观察尚未完成。
> 插件版本：`0.13.0`；SQLite schema 升到 v9。

## 1. 目标

M4 把网页版从“会聊天、会记忆”推进到“会自己安排、偶尔主动联系、能接提醒、每天整理”的日常陪伴基线：

- 只使用一个后台调度循环，不制造多套定时器；
- 每天生成可自行调整的软性生活计划；
- 主动消息经过安静时段、聊天冷却、忙碌状态、节奏和熔断闸门；
- 用户委托的提醒在确认后才生效，并且不受安静时段影响；
- 出站消息进入 outbox，具备幂等、有限重试和过期语义；
- 每天整理前一天对话，保存摘要和来源可追溯的记忆候选；
- 自动清除到期回收站内容，并保留每日备份；
- 网页显示主动性状态，并能在页面位于后台时发送浏览器通知。

## 2. 已实现

### 2.1 单一调度循环

- `InitiativeScheduler` 只创建一个 `setInterval`，计划、提醒和 outbox 都复用同一个 tick。
- 上一轮尚未结束时跳过下一次，避免重入和重复投递。
- 插件停用时清理唯一 timer、abort 在途模型调用，再按需要等待 tick 结束后关闭数据库。
- tick 间隔来自 `initiative.toml` 的 `schedule.tick_seconds`，限制在 10～3600 秒。

### 2.2 软性生活计划

- 每天达到 `schedule.daily_plan_at` 后生成一次当天计划。
- 模型只能返回有限的活动类型、标题和时长；时间落位由确定性代码在 `life.day_start_at`～`life.day_end_at` 内排布。
- 晚启动时不倒填已经过去的时段，也不会重复生成同一天计划。
- 计划保存到 `life_plan_items`，网页可查看；它当前是软计划，不代表已经执行了读书、游戏或浏览活动。
- 用户明确安排、睡眠、承诺和提醒仍由上下文和上层规则约束；当前还没有结构化日程表，不能把提示词约束说成硬编码日历引擎。

### 2.3 主动消息

- 主动评估间隔默认 60～120 分钟，带随机抖动；评估不等于发送。
- 连续未回复会按配置倍率放慢，且间隔有 24 小时上限。
- 闸门顺序包含：紧急停止、功能关闭、熔断、安静时段、最近聊天冷却、忙碌状态、未到评估时间。
- 主动草稿进入 outbox 后，发送前再次检查安静时段、熔断、是否早于本次启动、用户是否已经回来聊天；任一失效就标记过期，不在重启后补发。
- 到期关心事项可以进入主动上下文，但只能在合适窗口自然提起一次。
- 主动消息仍使用占位身份生成；真实人格效果尚未验收。

### 2.4 outbox

- 出站种类包括 `proactive`、`reminder`、`system` 和迁移后的 `legacy`。
- 状态转换为 `pending → sending → delivered/failed/unknown`，终态不可重新打开；失败可按上限重新排队。
- outbox 记录最大尝试次数、退避时间、过期时间、错误代码和已投递消息引用。
- 进程中断留下的陈旧 `sending` 记录可以恢复；已过期或超过尝试次数的记录不会被无限重试。

### 2.5 提醒与关心事项

- 模型只能从明确委托中提出提醒候选；候选先进入 `pending`，不会直接发送或创建有效提醒。
- 所有者确认后才创建 `confirmed` 提醒；拒绝保留候选结果但不会触发投递。
- 提醒到点后照常发送，不受安静时段和主动消息熔断影响；只有紧急停止和所有者取消能拦住。
- 提醒正文通过正文引用保存，确认不会复制第二份正文。
- 关心事项有 `dueFrom`、`dueUntil`、最大窗口和最大提前天数；过期后自动变为 `expired`，投递一次后变为 `delivered`。
- 同一轮 JSON 信封内重复的提醒和关心候选会被去重。

### 2.6 每日整理

- 默认每天 00:30 后整理前一个本地日；错过时在下一次启动后的 tick 补做。
- 每次最多读取配置数量的消息，失败按每日上限重试，不无限循环。
- 摘要写入 `daily_summaries`，并保存当天消息 ID 作为来源。
- 模型返回的记忆候选必须带当天真实消息 ID；来源不成立的内容不写入。
- 整理得到的记忆按 `rinko_inferred` 进入候选门禁，不因模型自称“重要”就绕过确认。
- 摘要正文和记忆候选复用可清除的 `bodies`，事件和审计不复制聊天正文。

### 2.7 维护与删除

- 每次 tick 执行 outbox 陈旧记录恢复、过期清理、关心事项过期和每日备份检查。
- 每个本地日最多执行一次到期回收站清除；失败会记录运行结果，下一天再尝试。
- 每日备份沿用 M2 的一致性备份和保留策略。

### 2.8 网页与通知

- 新增“主动性”页签，显示开关、安静状态、上次/下次主动时间、连续未回复数、熔断、软计划、提醒候选、提醒、关心事项、每日摘要和最近运行记录。
- 支持确认/拒绝提醒候选、取消提醒和手动恢复熔断；所有写操作要求 DSH 登录态和 `{"confirm": true}`。
- 页面每 30 秒轮询，并在重新可见时刷新；聊天完成后也刷新主动性面板。
- 浏览器通知只针对与 `lastProactiveAt` 对应且新出现的主动消息，不会把页面隐藏期间产生的普通聊天回复误报为主动消息。
- 浏览器通知要求页面仍开着且用户授予通知权限；它不是 Web Push，电脑关机或浏览器完全关闭时收不到。

### 2.9 存储与迁移

- `reminder_candidates`
- `reminders`

- `outbox` 的种类、状态、尝试次数、退避、过期和投递消息字段

v8 → v9 迁移保留聊天、记忆和模型调用历史；旧 outbox 记录变为 `legacy`，补齐 `updated_at` 和默认最大尝试次数。

## 3. 配置

新增 `config/examples/initiative.toml`，按模块承载：

- `[schedule]`：tick、每日计划、每日整理时间；
- `[proactive]`：开关、间隔、冷却、熔断、长沉默参考线、未回复降频、关心窗口；
- `[reminders]`：开关和最大提前天数；
- `[outbox]`：最大尝试、退避和过期；
- `[life]`：软计划开关、数量上限、活动窗口和间隔；
- `[review]`：每日整理开关、消息上限和失败重试上限。

默认值包括：北京时间、00:10～07:00 安静时段、60～120 分钟评估间隔、15 分钟聊天冷却、10 分钟内 3 条主动消息熔断、07:05 生成计划、00:30 整理前一天。

## 4. 自动验证

新增测试覆盖：

- 主动闸门、间隔、未回复放慢、24 小时上限和本地日边界；
- 24 小时仿真中每次回复、主动消息数量落在 8～17 条且不进入安静时段；
- 安静时段不主动但提醒照发；
- 熔断、关心项一次使用、旧草稿在安静/回聊/熔断/重启后过期；
- 晚启动计划不倒填、不重复生成；
- 每日摘要、来源引用和记忆候选去重；
- 提醒候选确认前不生效、确认后只投递一次、失败状态可解释；
- outbox 幂等和关心项释放；
- JSON 信封中的提醒/关心候选在聊天链路中只进入候选，功能关闭或超出时间范围时计数为跳过；
- schema v9 迁移、HTTP 鉴权、确认字段、提醒操作、熔断恢复和页面资源。

## 5. 未验证与边界

- 自动测试全部使用脚本化 brain、mock 模型、手动时钟和临时数据库，没有调用真实模型，也没有读取正式人格。
- 主动消息是否自然、是否符合燐子人格、长时间未回复时是否表达得当，仍需真实模型和实际对话样本验证。
- 24 小时仿真证明的是确定性调度和闸门，不证明真实模型会持续产生有意义的主动素材。
- 浏览器通知只做了静态资源和逻辑测试，尚未在真实 Windows 浏览器上做后台通知人工验收。
- 当前没有 Web Push、邮件或 QQ 推送；电脑关机、浏览器完全关闭时无法收到主动消息。
- 当前没有实际执行生活计划。读书、游戏、浏览和桌面活动仍属于后续数字生活模块。
- 当前没有结构化用户日程；用户安排通过聊天上下文和提示词约束，不等于不可绕过的日历硬约束。
- 每日整理产生的推断记忆仍是候选，需要所有者确认；自动证据累积、长期升权和普通记忆淡化仍属于后续记忆改进。
- QQ、NapCat、多图逻辑回合、统一多模态、VM、浏览器自主浏览、游戏和公开发送均不在 M4 范围。
