## 2. 已实现内容

### 2.1 单次对话信封

- 一轮聊天只调用一次模型，`purpose` 固定为 `chat`。
- 模型输出一个 JSON 对象，字段为：
  - `schemaVersion`；
  - `reply`；
  - `memoryCandidates`；
  - `appraisal`；
  - `commitments`。
- Magpie 驱动在 `jsonMode=true` 时发送 `response_format={"type":"json_object"}`；普通文本调用不发送该字段。
- `ReplyEnvelopeStream` 增量扫描顶层 `reply` 字符串，转义、Unicode 代理对和任意分片都不会造成重复文字。
- JSON 尾部损坏但 `reply` 已完整闭合时，保留正文、丢弃元数据并记录 `chat_envelope_invalid_json`；`reply` 本身不完整时按模型输出失败处理。
- 有字段被门禁丢弃时，正文仍可用，但 `envelope.ok=false`，并通过 `issueCodes` 明确报告降级原因。

### 2.2 记忆候选

- 记忆候选复用原有关联引用、来源降级、敏感内容、第三人内容、置信度和去重门禁。
- 用户原话可直接成为 `user_stated`；只有助手回复作为引用时降级为 `rinko_inferred`。
- 敏感内容和第三人内容仍只进入候选，不能靠模型自报绕过转正。
- 旧的独立 `memory_extraction` 服务和调用已移除；数据库枚举保留，仅用于解释 M3.3 及更早的历史审计行。

### 2.3 状态与承诺

- `appraisal` 经校验后写入 `appraisal.recorded` 事件，由纯 reducer 按置信度更新虚拟心情。
- `commitments` 的正文写入 `bodies`，正文 ID 和可选 `dueAt` 写入 `commitment.created` 事件。
- `done.state` 新增 affect、relationship 和 commitments 摘要；网页显示心情、关系与未完成承诺数。
- 单个字段损坏不会吞掉已经保存的正文；部分字段被丢弃会在聊天消息下显示提示。

### 2.4 网页与版本

- 页面标题更新为“Kanobot · M3.5 聊天、记忆与状态”。
- 状态页新增心情、关系和承诺；边界文案改为单次信封和逐字正文。
- 插件版本从 `0.7.0` 升到 `0.8.0`，同步修改 `package.json`、`package-lock.json` 和 `src/plugin/version.ts`。
- SQLite schema 保持 v6，没有新增迁移。

## 5. 尚未完成与已知边界

- `reply` 已经流式显示后不重新调用模型；JSON 尾部损坏会保留正文并丢弃元数据，这是为了不出现两份正文。没有“解析失败后隐藏已显示文本再重试”的机制。
- 当前提示词没有注入当前时间和“上次说话时间”，所以“明早”这类相对时间可能得到 `dueAt=null`。承诺记录已经闭环，但提醒解析和调度仍属于 M4。
- 视觉输入尚未接入；设计上必须使用独立配置的视觉模型，不能写死 Gemini 或其他模型名。
- 主模型比较和选型尚未进行，按 kano 的决定后置到整个项目完工后；当前只验证配置中的 DeepSeek Flash 路由。
- 风格检查失败仍只记录并照常发送，不会自动重新生成。
- 7 个场景仍使用脚本化占位回复；本切片没有新增真实模型场景比较。
- 当前没有自主调度器，因此 `appraisal` 和 `commitments` 只验证了持久化与网页读取，尚未用于主动消息或提醒。
