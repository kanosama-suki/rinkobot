# M4.5 发行基础验收

> 日期：2026-11-07
> 插件/程序版本：`0.14.0`
> SQLite schema：v9
> 结论：双形态、模型 provider、设置页、密钥与端点治理的发行基础已完成。M4.5 不改变人格、记忆和状态语义。

## 1. 范围与边界

本阶段完成的是同一陪伴核心的两个宿主：

- DSH Host 插件；
- 独立程序。

两者共用 `src/core`、SQLite schema、迁移、备份、网页表面和模型 provider 接口，不维护第二套人格或记忆。`src/dev` 仍只是开发入口，不是正式产品。

验收只操作隔离测试目录和 `127.0.0.1:4100`。正式 `4096` 没有修改、没有重启，本文不记录测试聊天正文、token、API key、Cookie、正式人格或私人配置。

## 2. 双形态

### 2.1 DSH 插件

- 入口仍是 `src/plugin/index.ts`，只在宿主适配层读取 DSH 服务。
- `webServer` 和 `connection` 是必需注入；`ctx.llm` 是可选的宿主能力，通过 Cordis 的 `ctx.reflect.get('llm')` 读取，不能直接访问未声明的 `ctx.llm`。
- 当聊天 provider 选择 `dsh` 时，必须同时具备 `ctx.llm`、精确 provider route、精确模型名和输出上限；缺任何一项都在打开存储和注册定时器前失败。
- 选择 `mock`、`magpie` 或 `openai-compatible` 时，不要求宿主提供 `ctx.llm`。
- 真实 4100 Profile 已加载 `0.14.0`；设置 API 返回 `hostCapabilities.dshChat.available = true`，启动报告和 stderr 无插件错误。

### 2.2 独立程序

正式入口：

```powershell
npm run app -- --config <配置目录> --data <数据目录> [--port 4200]
```

边界：

- `configDir` 和 `dataDir` 必须显式提供，且不能是同一目录；不回退到 `config/examples` 或 `tmp`。
- 只监听 `127.0.0.1`，默认端口 `4200`。
- 启动终端打印一次性 bootstrap 地址；默认 10 分钟内有效，成功使用一次后作废。
- bootstrap 换取短期 HttpOnly、SameSite=Strict Cookie，默认 8 小时过期；地址栏重定向到不含 token 的 `/kanobot/`。
- 页面、静态资源、聊天、记忆、主动性、审计、控制和设置 API 共用同一个鉴权入口。
- 非预期 Host、跨源 Origin 和未认证请求分别 fail-closed。
- 独立程序不暴露 DSH provider；设置页明确显示 DSH 不可用，保存端仍会再次拒绝。

自动集成测试用真实回环 HTTP、mock 模型和临时目录验证了一次性登录、Cookie 鉴权、聊天持久化、重启恢复、端口释放和 schema v9。

### 2.3 共用数据契约

- 两个入口共用 schema v9 和同一迁移代码。
- provider 切换测试保留原人格文件、对话、长期记忆和状态；只改变模型身份。
- 插件和独立程序不复制核心，不建立第二套数据库。
- 跨宿主或升级前应停止进程并复制整个数据目录，包含主库、`tombstones.sqlite` 和备份；不能只复制主库。主库日备份不包含独立墓碑库。

## 3. 模型 provider

`src/model-providers` 是唯一把配置转换成 `ChatModel` / `VisionModel` 的装配点。

| provider | 使用范围 | 边界 |
| --- | --- | --- |
| `mock` | 测试和离线开发 | 不联网；不接受端点和 API key |
| `magpie` | 本机 Magpie 路由 | 只允许回环 `/v1`；可配置环境变量或本地 secret；保留 Magpie session header |
| `dsh` | 仅 DSH 插件 | 精确 route + model；要求 `ctx.llm` 和显式文本能力；不支持 assistant prefill 或 JSON response mode；只在可见正文出现前有限重试 |
| `openai-compatible` | 受控第三方或自建兼容端点 | 默认 HTTPS；精确 `/v1` 模型校验；默认拒绝私网/回环，需显式允许；不发送 Magpie session header |

聊天和视觉模型独立配置：

- 视觉 provider 当前只支持 `magpie` 和 `openai-compatible`；
- 启用视觉时必须提供精确模型、端点和输出上限；
- 启动检查要求上游明确声明图片输入能力；
- 图片只在当轮内存中交给视觉模型，不写入正文、事件、快照、记忆或审计；
- 视觉失败不得回退到聊天模型假装看过图片。

所有真实 provider 在启动前完成连接和能力检查；缺路由、缺凭据、错 URL、错模型、超输出上限或不支持所需能力都会阻止启动，不自动降级到 mock 或另一个模型。

## 4. 设置页与运行时配置

页面新增“设置”页签，聊天和视觉模型分开管理：

- provider、精确模型名、DSH route、Base URL、超时、重试、输出上限和推理档位；
- 聊天与视觉分别选择“保留当前来源”“不配置”“环境变量”或“写入新密钥”；
- 连接/能力测试先于保存；失败不写运行时覆盖；
- 保存后需要重启宿主才切换，不做热更新；
- 仓库 `config/examples` 只读，避免页面改动模板；
- 设置 API 只返回凭据模式、环境变量名或本地标签，不返回密钥值或 secret 引用。
- 旧 Profile 的 `modelMode: magpie` 不再遮蔽设置页保存的 provider；该兼容字段现在只保留测试所需的强制 `mock`。

运行时覆盖写入配置目录的 `model-settings.json`，只允许覆盖 `model` 和 `vision` 段。JSON `null` 表示删除 TOML 基线中的同名字段，用于切换 provider 时明确清理旧的端点、凭据和推理档位。未知字段、错误类型和非法值会 fail-closed，并指向真正的覆盖文件。

## 5. 密钥与端点安全

### 5.1 密钥

支持两种来源，二选一：

- 环境变量：配置只保存变量名；
- 本地加密 secret store：AES-256-GCM，密钥与密文分文件保存，目录和文件尽力限制为当前用户可读写。

密钥不进入 TOML、SQLite、审计、快照、普通日志或页面。错误消息只报告文件/字段/引用类型，不回显明文或密文。

已知边界：Windows 上 `chmod` 不等于完整 ACL；加密主密钥与密文位于同一配置目录，不能抵御已经取得同一 Windows 账号文件访问权的攻击者。它不是 DPAPI、凭据管理器或硬件密钥库。

### 5.2 第三方端点

- 静态配置拒绝 URL 内嵌凭据、query/fragment 和非 `/v1` 路径；
- `magpie` 只接受回环主机；
- `openai-compatible` 默认要求 HTTPS；私网、回环和 HTTP 需要显式 `allow_private_network`；
- 每次连接前解析 DNS，拒绝私网、回环、链路本地、保留地址和云元数据主机；
- 请求使用 `redirect: error`，避免 3xx 把已授权地址变成任意探测；
- 连接测试只检查已填写端点，不提供任意 URL 探测接口。

已知 P2：DNS 预检与实际 `fetch` 的解析之间仍有 DNS rebinding 时间窗。当前依靠 HTTPS、私网默认拒绝、DNS 预检和禁止重定向缓解，但没有把连接固定到预检得到的 IP。

## 6. 验收中发现并修复的缺陷

### P1：真实 Cordis 宿主拒绝直接读取 `ctx.llm`

首次重启 4100 时，DSH 报告：

```text
cannot get property "llm" without inject
```

原因是插件把 `llm` 当作普通可选属性读取，而 Cordis 只允许读取已注入服务。fake context 测试没有模拟这一限制，因此没有提前发现。

修复：

- 插件不再直接读取 `ctx.llm`；
- 通过 Cordis 的 `ctx.reflect.get('llm')` 读取可选服务；
- 若服务存在但结构不符合窄接口，明确失败；
- 测试上下文增加会抛错的直接 `llm` getter，防止以后绕过 reflect。

修复后 4100 成功加载，生命周期测试 7/7 通过。
